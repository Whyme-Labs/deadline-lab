# Deadline Lab implementation checkpoint

9 November 2026. Local scaffold v0.1.0.

## Decision

The idea now has an executable implementation beyond the earlier Python state model. It can kill or suspend real compiled C workers, observe resulting synthetic effects, find seeded recovery failures in generated histories, reduce those histories, and export regression tests.

This increases confidence that the workflow can be built and demonstrated. It does not establish a probability of winning. The decisive competitive gap is still native QNX execution and usefulness on an independently authored application.

## What changed in this session

The portable contract is implemented in C11 and compiled with strict warnings. A Python standard-library runner owns isolated workers and a separate virtual-plant process. Real SIGSTOP/SIGCONT and SIGKILL operations supplement explicit delivery/acknowledgement fault hooks. The checker uses issued-command records and plant effects instead of trusting a worker's success reply.

The generator combines a bounded action grammar without inspecting the fixture mutation. The reducer removes actions while repeatedly checking that the same property fails. The exporter writes reusable scenarios and a regression suite with JUnit output. A standalone HTML viewer displays the recorded evidence and supports filtering.

Native QNX client/server source, a toolchain definition, setup checks and a target canary script were added. Those are source only. No QNX headers were mocked to manufacture a green compilation result.

## Main campaign

Eighty generated histories were each run against six C implementations, for 480 scenario executions. Forty seeds formed the discovery set and forty separate seeds formed the held-out set. These are process-level executions, not 480 independent applications and not additional repetitions of the earlier 4,000-model-history experiment.

| Implementation | Runs | Pass | Fail | Inconclusive |
| --- | ---: | ---: | ---: | ---: |
| Reference guards | 80 | 80 | 0 | 0 |
| Generation guard removed | 80 | 12 | 68 | 0 |
| Expiry guard removed | 80 | 56 | 24 | 0 |
| Cancellation guard removed | 80 | 34 | 46 | 0 |
| Deduplication guard removed | 80 | 11 | 69 | 0 |
| Reject every command | 80 | 0 | 80 | 0 |

The reference produced 301 observed effects, including all 80 required healthy probes. The reject-all control failed every history because it could not make healthy progress. Different histories activate different faults, so an individual mutant can pass a history that does not expose its omitted guard. These detection counts are not general bug-detection rates or prize probabilities.

Every seeded defect family was exposed in both the discovery and held-out sets. No real QNX or production-software vulnerability was discovered.

Each accepted reduction was reproduced twice. Final witnesses were independently replayed five times on each implementation. All four passed a one-deletion audit within the valid scenario grammar. This is local deletion-1-minimality, not global shortest-sequence proof.

The exported suite ran four reference checks and four mutant-sensitivity checks. All eight expected outcomes occurred. The regression test unit suite also substituted a faulty candidate and confirmed that the exported test failed with a JUnit failure entry.

## Validation

- 28 Python unit/integration tests passed, including missing, modified, reordered and truncated evidence, malformed input, subprocess isolation and regression export.
- The C executable completed 1,052 contract assertions, including expiry equality, cancellation, conflicting IDs and full deduplication storage.
- Clang AddressSanitizer and UndefinedBehaviorSanitizer completed the C test executable and six process scenarios with no diagnostics observed.
- Clang static analysis reported no diagnostics on the two portable C sources in the executed invocation.
- All 480 saved run manifests were checked and all 480 independent offline oracle re-evaluations matched their recorded verdict and violations. These rechecks are not counted as new process executions.
- Chromium rendered the generated HTML with no page script errors. The campaign table contained 480 rows and its reference filter showed 80. Desktop and mobile screenshots are included. This validates the in-memory rendered content, not file-origin browser navigation.

A source-only copy in a fresh directory rebuilt the binaries and passed the one-command verification, including all 28 Python tests and all eight regression expectations. No existing build directory, package installation or network access was used. The record is `evidence/clean-copy-verification.txt`, with a machine-readable summary in `evidence/clean-copy-summary.json`.

## What did not run

`qcc`, `QCC` and both checked QEMU binaries were absent from PATH. The QNX build helper exited 77 with an explicit blocker. The target canary returned NOT_RUN on Linux. This is evidence about the present container, not a claim about the user's remote machines.

No physical actuator, motor electrical model, thermal model or mechanical prototype was used. The integer plant demonstrates effects, not motor dynamics. The authorisation deadline is distinct from a physical actuation deadline. Durable exactly-once physical effects and cross-reboot device reconciliation remain outside scope.

## Execution issues and fixes

An early campaign hit the tool-call wall-time limit. Investigation showed that this environment's Python site initialisation dominated the cost of each plant subprocess. The plant uses only the standard library, so launching it with `python -S` removed that unnecessary startup cost. An empty scenario dropped from roughly 0.7 seconds to roughly 0.04 seconds in the observed local check. Those observations are not a portable performance claim.

The larger campaign also exceeded a tool-call budget during collection. It resumed from completed, hash-verified run checkpoints. The interrupted partial run was preserved and not counted as a completed result. No timed-out or incomplete run was silently converted into a pass.

The default Playwright browser binary was missing. The installed Chromium was used instead. Its policy blocked file-URL navigation, so the team's own generated HTML was rendered in memory without changing browser policy. This is documented in the browser evidence record.

## Assessment for the competition

The project can now demonstrate an operational bug-to-regression workflow rather than narrate it. That is meaningful progress on implementation, reproducibility and evidence quality. The seeded cases make the test system's sensitivity inspectable, and the healthy probe prevents a trivial reject-all implementation from looking correct.

The remaining weaknesses are material. The target-specific canary has not compiled or run. All exercised application logic is ours. We have not shown that an outside developer saves time, or that an external application has a defect the tool finds. Generic fault injection and delta debugging already exist. A polished report alone does not establish differentiation.

The next gate is a licensed QNX 8 build and repeated native timeout/unblock observations. Then connect that path to the reducer and integrate an independently authored sample. That evidence, not more synthetic test volume, should determine whether the entry is strong enough to submit.
